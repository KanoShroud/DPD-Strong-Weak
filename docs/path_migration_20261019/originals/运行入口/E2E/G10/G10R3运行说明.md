# G10-R3轻量AP效率验证

入口：`G10R3轻量AP验证一键运行.py`，解释器使用项目PyTorch环境。无需修改PyCharm工作目录。

## 点击顺序

1. R2/SBL仍在运行：显示“R3未启动”并正常退出，不使用GPU，不影响R2。
2. R2结束后首次点击：执行正确性核验和24例有限计时短测，保存结果后退出，不连着运行正式比较。
3. 短测放行后再次点击：执行120例×四版本的独立比较。未放行时只提示回读，不自动调整参数。
4. 中断后再次点击：恢复当前阶段，已完成记录不重复计算。全部完成后只显示结果位置。

当前V2短测只复核两种AP的共同完整梯度停止，各五次计时，共240次求解，另有正确性检查。旧V1的384次结果保留，原NOMP/ML不重跑。正式仍为四方法480次求解；准备完成后依据实测求解及逐任务开销估计预算，不沿用R2耗时。

## 日志和结果

- 阶段开始/结束单独提示；每15秒刷新同一行进度条，显示完成数、用时和ETA，不输出逐迭代日志。
- 输出根：`outputs_e2e/unified/e2e_g10/r3/`。
- `preparation.json`指向短测，`active_run.json`指向正式结果；两者均保存绝对路径。
- 每阶段回读：`运行摘要.md`、`comparison_report.json`、`paired_cost.csv`、`final_audit_report.json`。
- 短测还需回读：`cpu_checks.json`、`gpu_checks.json`、`readiness.json`。
- 图表位于`figures/`，包含PDF、600dpi PNG、CSV和双语图注；汇总表包含CSV、Markdown和LaTeX。

## 可选参数

- `--check-only`：只读检查R2参考身份、活动进程与准备指针，不执行定位。
- `--prepare`：只完成/恢复短测，完成后仍退出。
- `--new-prepare`：在代码修订后新建短测目录，保留旧失败或过时证据；不得用来掩盖同一版本失败。
- `--replot <绝对结果目录>`：只读保存的逐例结果重绘，不重新定位。图表导出也避开SBL计算期间。

未完成GPU核验和计时前，代码构建完成不等于正式放行。若检查显示停止精度不一致或提速不能保留，先回读原因；入口不会为了继续推进而改变停止条件、样本或算法。
