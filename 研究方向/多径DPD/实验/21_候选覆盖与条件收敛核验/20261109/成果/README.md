# 第21轮：候选覆盖与条件收敛核验

**当前状态：代码与执行合同已构建，尚未运行本轮冻结IQ。**

这是对[第20轮负面结果](../../20_分支可区分性核验/20261109/成果/第20轮实验结果与科研判断.md)的有限科研诊断，目标是区分前端候选缺失、6点/6对压缩遗漏、反射路径预算欠拟合与固定位置条件求解不充分，而非构造新的定位算法。

## 入口

在已有本地仓库用PyCharm打开 `一键运行_第21轮.py`，点击绿色运行箭头或右键 Run。**不需要任何其他配置。** 它自动：

1. 运行不读取冻结IQ的数学及接口自检 `test_round21.py`；
2. 检查原第09轮 `common18` 的3个冻结IQ，逐个校验登记SHA；
3. 执行每组两条仅由完整IQ构造的盲位置对条件多径拟合：同一支持、同起点分别70/300次SLSQP；
4. 先将三条盲决策全部写盘，随后才读真值做离线近真候选控制，最后审计第20轮的保存数据；
5. 每次新建 `../运行数据/pilot3_时间戳/` 输出，不触及旧MP、已有运行数据或原IQ。

计划条件：L0测K=0/4；L1测K=4/8；L2测K=4/16，其中K是全网络反射支持的**固定诊断预算**而不是算法知道的真实路径数。每次在相同输入和支持条件下对照70和300次SLSQP；严格保持PG≤1e-7。**任一数值准入未通过就标记不可判定，不允许宣称模型不可辨识。**

[正式执行合同与研究判别门](执行合同与研究判别门.md)。

## 开发与结果边界

- 本轮预先仅运行3条已见开发IQ，不从18条中更换有利样本，不做正式扩量。
- 真实位置只进入评价和ORACLE对照，不进入任何盲选择、增径、求解和停止。
- K=16相较K=4明显增加模型复杂度，结果可能过拟合或数值不收敛，不是“更大K必优”的性能试验。
- 不允许将测试脚本单元PASS或PyCharm退出码0解释为科研假设成立。
- 运行后将实验JSON提交推送GitHub，其他研究者可在不接触本地NPZ的情况下审计判别结论。
