# AGENTS.md

本文件记录本项目稳定适用的仓库协作规则，不记录当前任务、实验结果、临时状态或研究路线。

## 环境与编码

- 当前环境为 Windows 11，默认 shell 为 PowerShell 7；命令使用 PowerShell 语法，不默认使用 Bash 语义。
- 项目 Python 解释器为 `D:\Software\anaconda3\envs\PyTorch\python.exe`。
- 缺少依赖时，先说明缺失项并提供 Conda 或 pip 安装命令；未经用户批准，不主动安装或修改环境。
- 读取中文路径、中文文档或中文注释时，PowerShell 使用 `Get-Content -Encoding UTF8 -LiteralPath ...` 等 UTF-8 安全方式。若仍乱码，应先确认实际编码，不得依据乱码内容修改文件。
- 新建或已确认采用 UTF-8 的文本文件，Python 读写时显式指定 `encoding="utf-8"`；外部文件保持原编码。
- Python 中处理路径优先使用 `pathlib.Path`；确需字符串路径时避免不安全的转义。

### E2E 路径隔离

- `F:\SourceCount_DPD\outputs`仅作冻结参考输入；本工作树的新数据、缓存、权重和结果统一写入`outputs_e2e/`。
- 禁止写入、移动、删除原`outputs`，也不得用链接将本地输出目录指向它。
- 训练、关键评价及正式证据生成前，按下文运行预检条款核对输入身份、读写根分离和输出目标；普通只读查询与静态检查不触发数据预检。
- 大型参考数据须先用无缓冲复制固化到`outputs_e2e/`并匹配登记SHA；训练和评价只读该快照，阶段前后复核身份，异常即停止。
- 冻结输入不得只依赖硬链接；压缩HDF5读取失败或普通SHA漂移时，不直接判定文件损坏，应依次检查重复字节流、无缓冲副本和科研dataset逻辑身份，未分类前停止使用该输入。

### Windows 子进程与日志

- Python 在 Windows 上调用 `subprocess.run(..., text=True)` 时必须显式指定实际编码和错误策略，不得依赖系统默认代码页。项目内 Python、Git、`nvidia-smi` 等 UTF-8/ASCII 输出统一使用 `encoding="utf-8", errors="replace"`；已确认输出为其他代码页的外部程序应显式声明对应编码，并将保存日志统一写为 UTF-8。
- 启动项目内 Python 子进程时，应显式设置 `PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8:replace`。长任务通过管道转发日志时优先按字节读取、显式解码；控制台转发还需使用安全替换，避免单个不可编码字符使读取线程退出并造成管道回压或假超时。
- 后台日志线程的异常必须传回主线程并写入阶段报告，禁止静默退出；读取 `stdout`、`stderr` 等可空字段前必须处理 `None`，避免原始异常被二次异常覆盖。
- 新建涉及中文路径、中文日志或子进程捕获的执行入口，在长任务前至少完成一次非 ASCII 输出捕获与报告写入检查。乱码只能作为编码待确认信号，不能据此修改源码、数据或实验结论。

## 审批与修改范围

- 用户要求“先出方案”“只检查”或“只分析”时，不修改文件。
- 实质性代码或文档修改，应先说明问题、影响范围和修改方案，经用户批准后执行。用户已明确要求实施所述方案时视为批准；同一范围内的实施、必要轻量验证及下述自动修复沿用已有授权，不重复确认。扩大范围、改变科研决策或增加敏感操作时再请求批准。
- 修改应保持小范围、可解释，并沿用现有代码和文档风格；不修改任务范围外文件。
- 保留用户和既有工作的未提交修改，不擅自回滚或覆盖。
- 避免无关格式化、批量替换、编码转换或整文件重写，尤其是包含中文注释的文件。

### 高置信工程小错的自动修复

- 执行已批准任务时，若失败根因明确且属于编码、日志转发、路径拼接、参数传递、导入遗漏、报告字段或同类低风险工程错误，Codex可直接实施最小修复并继续，无需再次请求审批。
- 自动继续必须同时满足：不改变算法、数据内容、数据划分、随机种子、模型结构、loss、优化配置、资源门槛、评价指标或科学判定；失败输出不被复用为通过证据；修复后通过针对性静态/轻量验证；受影响阶段从全新目录或全新输出文件重新运行。
- 自动修复和重跑应在下一次进度更新及最终交付中说明根因、修改和新旧证据目录。根因不唯一、同一问题重复出现或轻量验证不足时，停止自动修改和重跑，可继续只读诊断；需改变科研语义、扩大资源预算或覆盖/删除证据时请求用户决策，不无界重试。
- 训练、关键评价及正式证据生成前，必须由文件系统重新解析输入路径并检查存在性、读写根分离与参考产物身份；已有权重或数据若有已知 SHA256，应核对哈希，不得仅凭对话记忆手写历史时间戳。新实验的输出目标必须为空或不存在，且不得指向冻结参考根。
- 已批准的恢复运行可使用登记的非空目录，但须先核对输入与合同身份、已完成证据及累计资源账本，保持原预算和停止条件；仅续跑未完成工作，不覆盖已完成证据。修复后失效阶段的重跑仍使用全新输出，未受影响的有效阶段可按登记状态复用。
- 总门禁应区分有效 PASS 证据与保留的失败尝试；失败目录不得删除或伪装为通过，汇总逻辑也不得因为保留失败证据而要求清理历史目录。

## 代码修改与验证

- 手工修改源码、配置和文档时优先使用 `apply_patch`。
- 修改 Python 文件后，使用项目解释器对本轮涉及文件执行语法编译；Ruff 可用时执行 `python -m ruff check <文件列表> --select F,E9`。
- 修改 MATLAB 文件后，使用 MATLAB Code Analyzer 或等价静态检查检查本轮涉及文件。
- 同一最终版本、相同输入与环境下已通过的检查可在本任务中复用；相关文件再变、检查失败或出现新风险时重跑受影响检查。正式运行预检及规定的阶段前后身份复核不因复用而省略。
- 修改数据处理、模型、损失函数、定位、评估或结果保存逻辑时，还应核对数据形状、坐标和索引约定、单位、训练/验证/评估目标及输出字段的一致性。
- 算法、数据或评价逻辑改变时，应通过与变更相适应的正式实验重新验证，不把旧结果用于新实现的性能结论。既有结果重算、事实纠错和文字修订可使用可追溯原始证据验证，并说明重算范围；若原始结果不足或变更需要新求解，另行审批正式运行。
- 正式训练、完整评估和长耗时仿真默认由用户在 PyCharm 或 MATLAB 中运行，除非用户明确要求 Codex 执行。

## 文档与结果记录

根目录维护以下长期文档，按事件更新，不要求每轮全部更新。“只检查”“只分析”“先出方案”“不修改文件”或“不修改文档”的要求优先；此时不写长期文档，需记录的内容先在回复中给出。

### 单一事实源与去重规则

- 同一事实只设一个主责文档。非主责文档最多保留一句综合结论和相对路径链接，不复制完整表格、指标组或事件经过。
- 新事实先更新主责文档，再按需更新其他文档的摘要或链接。发现冲突时以主责文档和原始结果文件为准，并修正其他副本。
- 阶段切换必须经用户明确确认；用户已明确批准的阶段及推进条件沿用授权，未批准的阶段或路线变化仍须确认。阶段文档中的 Gate 使用 `S<阶段号>-G<序号>` 编号，避免与跨阶段的历史 Gate 混淆。

### 按需读取与证据规范

- 恢复项目背景或分析论文与代码关系时，优先读取 `对话上下文.md` 和 `研究总结.md`。
- 执行主线工作前确认 `当前任务.md` 中相关任务与授权；追溯代码修改或实验事实时，分别检索 `修改记录.md` 和 `实验结果记录.md`。已有上下文足够且文件未变时不重复读取；局部任务只读取相关章节，不自动恢复全部研究背景。
- 没有实际运行实验、读取原始结果文件或获得明确用户反馈时，不写具体指标；用户口述结果必须标注“用户反馈/待复核”。
