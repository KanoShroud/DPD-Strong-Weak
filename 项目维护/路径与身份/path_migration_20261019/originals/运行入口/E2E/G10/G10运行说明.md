# G10零中心多方法比较

## 放行条件

当前执行状态见根目录`当前任务.md`；精确准备配置、正式结果和审计见`实验结果记录.md`的G10相关章节。不要从工程示例图判断方法优劣。

入口为本目录`G10多方法比较一键运行.py`。只有`outputs_e2e/unified/e2e_g10/release.json`存在且其准备报告、冻结配置和源文件身份一致，才能正式启动。无release时明确报“尚未放行”，不要改掉检查或运行旧G9入口替代。

使用项目解释器`D:\Software\anaconda3\envs\PyTorch\python.exe`。不需要额外安装进度条库。程序约每30秒或阶段变化时显示进度、已耗时与预计剩余时间；PyCharm启用“Emulate terminal in output console”可将进度条保持在同一行，不启用也可运行。

## 正式运行与恢复

点击运行：核对release，建立独立formal目录，生成冻结IQ，顺序执行八轨、统计、绘图和审计。不启动训练，不访问旧test或修改原outputs。总累计预算12小时；预算、资源或数值异常会保留结果停止。

再次点击：`active_run.json`指向同一正式目录，验证合同后跳过完成的样本—方法任务。进程被强制关闭时，未提交任务按其预留时间计费，并重新计算该任务；不把不完整行作为成绩。正常完成后再点击不重复实验。不要手工删除ledger、release或active_run以重置预算。

## 回读和图表

结果路径在启动日志中显示，回读：

- `运行摘要.md`、`status.json`；
- `comparison_report.json`、`summary_table.csv`；
- `cost_table.csv`（各方法完整耗时与运算次数）；
- `final_audit_report.json`；
- `figures/`内PDF、600dpi PNG、CSV、JSON来源和中英文图注。

`summary_table.tex`可用于后续Ho报告插入；本入口不改Ho报告正文。典型空间图按预登记布局选择，SBL使用后验功率，联合LS切片固定的是估计位置，不是真位置。

每次启动的公共预热单列在`warmups.json`，不计入逐样本算法时间，但计入总任务预算。累计预算及输入写入恢复已做工程检查；出现真正的数据身份不一致时保留现场停止，不自动覆盖。

## 只重绘

将入口中的`MODE = 'run'`改为`MODE = 'replot'`，只读取当前结果重新统计和绘图，不执行定位；改动入口后正式续跑的源码身份校验将拒绝，因此需在正式完成后使用。更推荐命令行独立重绘（不改入口）：

```powershell
& 'D:\Software\anaconda3\envs\PyTorch\python.exe' -m 统一模型代码.gates.g10.runner replot --out '完整结果目录'
```

短测目录的图带有DEVELOPMENT或ENGINEERING SMOKE标记，不能当正式论文性能图。
