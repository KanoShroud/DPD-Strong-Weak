# 当前多径 DPD 研究：目录盘点与集中整理方案

核验日期：2026-11-05。2026-11-06更新：**用户批准后已执行搬移与现用代码抽离，详见[当前导航](F:/DPD_Strong_Weak/docs/mp_dpd/README.md)。以下保留原审批方案；本次按用户最新要求采用数量/大小和固定输入运行核对，不做全文件哈希。**

## 1. 结论先行

需要整理，而且不宜只按日期把旧目录剪切走。当前 `outputs_e2e/research_admission_20261027` 同时承担了运行源码、跨轮公共库、冻结数据、源码快照、结果与文档六种职责。直接移动会破坏导入、输出根、断点续跑身份与报告链接。

建议采用“**先建立时间线与身份映射 → 抽离当前可运行代码 → 验证解耦 → 按主题和轮次迁移历史证据 → 切换入口与文档**”。这是一项工程整理，不借机更改算法、场景、门槛或历史结论。当前 0/1/2 反射范围也不因整理自动放行大实验。

## 2. 实际盘点

以下来自本轮文件系统枚举，不是人工估算。目录数不含该范围的根目录；文件数包含缓存和历史快照。

主要体积来自 `xia_scale_20261103`（约 3,175 MiB）、`unknown_order_20261030`（约 2,303 MiB）、`risk_calibration_20261102`（约 2,029 MiB）及 `risk_bootstrap_20261103`（约 1,909 MiB）。整理不等于清理这些证据。

本轮形成的可审计清单：

- `inventory_summary.json`：各一级主题目录的文件/目录/体积/源码数。
- `file_manifest.json`：所有文件的相对路径、大小、mtime；所有 Python 的 SHA256。**尚不是全体大文件的内容哈希迁移清单。**
- `python_reference_lines.json`：251 条静态路径/导入线索；不是完整运行时依赖图。
- `external_reference_lines.json`：254 条长期文档/入口/正式源码对这棵研究树的引用。
- `inventory.py`：只读取旧树、向本盘点目录写清单；不导入旧研究代码、不运行定位。

## 3. 为什么不能直接移动：具体证据

| 类别 | 已核对的例子 | 搬移风险 |
|---|---|---|
| 跨轮源码导入 | `soft_objective_20261105/soft_v2.py:9–12` 从相邻 `regularization_gate_20261105` 导入；其 `discrepancy.py` 又导入 `numerical_repair_20261104/stable.py` | 按日期拆成不同父目录后导入失效 |
| 递归历史依赖 | `stable.py:8–11` 导入 `inside_pilot_20261104/run_inside.py`；后者加载 `four_station_physical_20261104/scene.py`、`adapters.py` | 当前内核实际依赖多轮试验脚本，不是独立模块 |
| 动态代码与全局绑定 | `four_station_physical_20261104/adapters.py:33–43` 用 `inspect.getsource`、字符串替换、`exec` 克隆函数；并在后文改写函数全局绑定 | 普通文本搜索不足以证明新旧运行语义一致；迁移不可顺手“优化”这些逻辑 |
| 父目录层数 | `four_station_physical_20261104/scene.py:12–14` 通过 `HERE/BASE/BASE.parents[2]` 得到项目根 | 新增一层主题目录会把输出根推到错误位置 |
| 一键入口 | 共 7 个 G11 入口硬编码当前树；如 `运行入口/E2E/G11/四站全内780条对比一键运行.py:9` | 用户旧入口可能找不到源码，也可能误启动已暂停的批次 |
| 身份与续跑 | `inside_pilot_20261104/run_inside.py:152–164` 记录绝对源码路径和 SHA；续跑严格比较 `identity.json` | 即使内容不变，地址变了也会触发身份不匹配；不能篡改旧账本假装原地未变 |
| 更早研究依赖 | `xia_pairing/preflight.py:18` 引用 `统一模型代码/gates/g8/scenes.py`；`xia_pairing/los_2d.py:9` 引用 `research_admission_20261025/core_multipath/model.py` | 当前研究树不是封闭包；不能只搬 20261027 就声称与早期路线完全解耦 |
| 报告与长期记录 | 根目录 `研究总结.md` 等多处链接原 HTML/MD；HTML 内相对链接及浏览器旧地址也存在 | 物理搬移后的报告需进行链接与页面 QA |

另外发现 40 个 `.db`、24 个 `.db-journal` 和 18 个 `.lock` 文件；仅凭存在不能断定有活跃写入。但迁移前必须检查所属进程/事务，不能移动正在写入的 SQLite 或实验目录。

## 5. 推荐目标结构（待批准）

延续项目“代码 / 运行入口 / 输出”的三层关系，不新建跨项目依赖，也不把所有旧结果塞回运行代码。当前研究采用独立轨道 ID `mp_dpd`；正式阶段编号须在盘点既有编号后确定，统一采用仓库要求的 `S<阶段>-G<序号>`，避免擅自宣布 G12 或重用历史 Gate。


新结构下：可执行主源码不再从 `outputs` 动态导入；输出中的源码只作冻结快照。数据和记录由显式路径合同传入，禁止依赖固定 `parents[n]` 定位项目根。共享的旧数学/物理工具若确需保留，应抽取有出处、可单测的项目内公共组件，或为当前轨道建立受控副本；不能留下对旧实验脚本的隐含导入，也不能静默复制后宣称原创。

历史运行结果仍按原运行边界整包保存。新索引可把它们聚合成主题与时间线，但不拆散 `identity + source snapshot + results + report`。不强制把每个历史小试验改造成新协议，更不批量重写旧结论。

## 6. 分阶段搬移、验收与回滚

1. **冻结与完整清单。** 检查活跃进程，确认没有正在写入的研究目录；登记 Git dirty 状态；对拟迁移全部文件计算 SHA256（当前仅 Python 已计算）；登记旧路径→新路径及角色，不覆盖已有目标。预计至少需 10.54 GiB 的临时副本空间，另留清单和安全余量，执行时检查实际磁盘可用空间。
2. **只建新骨架与导航。** 建立主题索引和时间线、选定当前工作入口；先不动证据。此时即可改善用户查阅，不必等全部代码解耦完成。
3. **抽离当前必要运行闭包。** 先处理确需继续执行的 Xia 锚定与当前 MP 内核，不把每个退休原型改写一遍。删除的是新工作副本中的隐式旧依赖，不删除历史快照。迁移与算法改进分开提交验收记录。
4. **固定输入等价检查。** 导入/语法/Ruff、数值目标与梯度、投影、种子生成 IQ、候选及固定回放输出应与原版本一致或符合预登记浮点容差；关闭旧树可读路径进行隔离测试，确认新入口不暗读旧源码。该工程验收不启动新的性能批次、不据此宣布 RMSE 更好。
5. **整包证据复制迁移。** 一批一批复制到已检查的精确目标，逐文件 SHA/数量/大小核验。旧 `identity.json` 原样保留；另外建立 relocation manifest，使用解析层将旧身份定位到新地址，不回填修改旧 hash 账本。断点续跑必须新增明确的迁移续跑合同，不直接让旧脚本静默继续。
6. **更新索引与入口。** 新入口读取新配置；旧的一键脚本显式跳转到获准的新入口或提示已冻结，不继续宣称780/3120已放行。修改长期文档当前入口和索引；历史报告仅在受控副本修正链接/加迁移导航，原始证据保存。检查本地 HTML 全链接、中文路径和页面展示。
7. **解除旧地址依赖后再清退。** 通过全量引用审计与完整固定回放后，旧目录暂存为可回滚备份。删除/回收旧大目录应另获明确授权，不能因“已复制”自动清理。无需采用硬链接或跨根联接掩盖未解耦。

每批失败立即回到旧入口和旧目录；保留失败迁移日志，不修改旧结果。只恢复本次改动的入口/配置，不用 `git reset --hard` 覆盖用户工作。

## 7. 本次建议审批边界

优先批准“建立时间线 + 完整清单 + 新工作骨架 + 当前执行闭包解耦”的第一批；确认验收后再搬移全量历史证据。文献精读和 Xia 锚定可以先在本轮独立目录完成，不必等待整棵历史树重构，但新的临时源码不要继续叠加到旧 `research_admission_20261027`。

本次没有搬移、删除、重写任何历史文件，没有更改算法或运行定位实验。`inventory.py` 已通过语法编译与 Ruff F/E9；其输出只证明静态目录事实，不证明迁移已经安全完成。
